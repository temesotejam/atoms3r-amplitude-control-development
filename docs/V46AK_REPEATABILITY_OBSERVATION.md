# V46ak / 0.46.36 — 次ピーク再現性の観測版

## 目的

V46ajで確定した姿勢推定・ZEROクロス判定・制御則を変更せず、
**同じような機体状態と制御入力でも次ピークがばらつく原因を調べるための状態観測**を追加します。

この版では、ホイール速度や実測直前電流を制御へフィードバックしません。
まず「次ピーク再現性の説明に本当に必要か」を実測で判断します。

## V46ajから変更しないもの

- 6-state MEKF
- 起動時ジャイロバイアス推定
- START同期中の立位MEKF再初期化
- MEKFの座標変換とYジャイロ感度補正 0.908911
- ピーク振幅に未補償MEKF角度を使う処理
- ZEROクロスに3 ms固定先読みを使う処理
- ZEROクロス角速度とsideによるrate-only自由次ピーク予測
- Qゲイン
- Ki = 0.10
- 300 mA、通常最大100 ms
- START_KICK
- ESTOP、IMU健全性監視、Roller出力ガード
- RWLOG v51のバイナリ時系列配置

姿勢推定の詳細は [現在の角度推定](ATTITUDE_ESTIMATION_V46AI_JA.md) を参照してください。

## 追加する観測

通常のAutonomous ZEROクロスイベントで、入力前状態として次を保存します。

| 項目 | 意味 |
|---|---|
| `i0_estimated_mA` | V46ajが従来から使う残留電流のモデル推定 |
| `pre_measured_current_mA` | ZEROクロス判断時点で利用可能な直近実測電流 |
| `pre_current_age_us` | その電流サンプルの鮮度 |
| `pre_wheel_speed_rpm` | ZEROクロス判断時点で利用可能な直近ホイール速度 |
| `pre_wheel_speed_age_us` | その速度サンプルの鮮度 |
| `vbat_mV` | 電源電圧 |
| `q_command_mA_s` | 選択されたQ |
| `q_effective_pred_mA_s` | 現行電流モデルのQ予測 |
| `pulse_width_ms` | 実際に選択されたパルス幅 |

パルス後には既存の電流監査による `q_meas_observed_mA_s` と、
停止指令を適用した後に取得したホイール速度を、その次の確定ピークへ紐付けます。

## ホイール速度の取得方法

Unit Roller485のI2C speed readbackを読み、RPMへ変換します。

重要なのは、**速度取得を制御判断の同期経路へ入れないこと**です。

- 通常時: Roller I/Oタスクの既存20 msテレメトリ周期で、モータ指令が0のときだけ取得
- パルス中: 追加の速度読出しをしない
- パルス終了時: まず0 mA / output offを適用し、その後で速度を1回取得
- 速度読出し失敗: 診断値をinvalidにするだけで、Roller READYや出力許可を変更しない

ZEROクロス制御側は、新しいI2C通信を行わず、
Core0からすでにpublish済みのテレメトリスナップショットだけを記録します。

## CSV

従来のCSVに加えて、

`energy_control_repeatability_events.csv`

を出力します。

これはZEROクロスイベントと、その指令に対応した次ピークを結合した表です。
主な列は次の通りです。

- ZEROクロス角速度 / side / 直前ピーク
- 予測次ピーク / 実次ピーク / 予測誤差
- Q command / Q predicted / Q measured
- 推定I0 / 実測直前電流 / 両者の差
- 入力前ホイール速度
- command方向に符号をそろえた入力前ホイール速度
- パルス後ホイール速度 / ホイール速度変化
- 電流・速度サンプルage
- Vbat / pulse width

この表を複数Runで比較し、

1. 現在の `rate + side + Q` だけで十分か
2. 直前電流を加えると別Runの予測誤差が下がるか
3. ホイール速度を加えると別Runの予測誤差が下がるか

を順番に判断します。

## この版でまだ行わないこと

- ホイール速度を次ピーク予測式へ入れる
- 実測直前電流をQ決定へ使う
- Qゲインの再同定
- Kiの変更
- rate-only baselineの係数変更

これらはV46akで取得した実測データを確認した後に判断します。

## 測定

まずV46ajと同じ条件を保つため、

- 目標: 8°
- 遅延補償: 3 ms固定
- 測定: 30秒
- 同じ機体・開始条件
- 各RunごとにRWLOGと動画を保存

で複数Runを取得します。

解析では同一Run内での当てはまりだけでなく、
**Runをまたいでも状態と入力から次ピークを再現できるか**を重視します。
